# Magic Shulker Boxes

**简体中文** | [English](en/guide.md)

适用于 **Minecraft Java 1.21.11 / Fabric / Java 21** 的潜影盒自动收纳模组。

**拾取自动入盒默认关闭。** 单人房主可在“世界设置”开启；多人服管理员可在统一配置中设置 `pickupStorageEnabled=true` 后执行 `/msb admin reload`，也可开放个人设置让玩家自行开启。自动取料使用独立开关。

拾取地面物品时，先放进玩家背包，放不下的余量再按以下顺序收纳：

1. **同类专用盒**：内部只有一种物品，而且与拾取物品同类。
2. **空潜影盒**。
3. **杂物盒**：内部已有两种或更多物品。
4. **其他单类盒**：默认关闭，可配置为最后的兜底。

前一类的所有可用盒子尝试完后才进入下一类；同一类优先填更接近装满的盒子，不能接收当前物品时跳过。装载程度按每格数量相对于该物品堆叠上限计算，兼容 64、16 及不可堆叠物品；相同时按背包栏位顺序。容量不足时可以只装入一部分，剩余物品留在地上。

## 升级到 0.3.2：个人开关与配置键改名

服务端允许个人设置（`allowPlayerSettings=true`）时，`pickupStorageEnabled` 和 `schematicRefill` 是**服务端默认值**，玩家可分别覆盖为开或关。关闭个人设置时，所有玩家统一使用服务端值。原 `enabled` 键已改名为 `pickupStorageEnabled`；新配置、命令和网络设置只接受新名称。

0.3.1 的 `configVersion: 1` 配置会在首次读取时完整备份到同目录的 `<原文件名>.pre-0.3.2.bak`，随后一次性改写为 `configVersion: 2`，保留原开关值及其余选项。服务端总配置、服务端保存的在线和离线玩家偏好、客户端偏好均会迁移。备份失败、已有同名但内容不同的备份或无效字段会保留原文件并报错。新版本的个人设置和取料通道已更新；使用这两项功能时客户端与服务端都需升级到 0.3.2。纯服务端入盒仍无需客户端安装。

## 升级到 0.3.1：备份并重置旧配置

0.3.0-alpha 及更早版本的配置没有版本标记。首次读取时，0.3.1 会把原文件完整备份为同目录的 `<原文件名>.pre-0.3.1.bak`，再全部重置；包括 `config/magic_shulker_boxes.json`、客户端 `config/magic_shulker_boxes-client.json` 和存档下 `data/magic_shulker_boxes/players/<UUID>.json`。服务端启动会处理已有玩家文件，包括离线玩家。客户端启动会处理本地偏好。

0.3.1 的统一配置恢复默认值：旧键 `enabled=false`、`allowPlayerSettings=false`；个人覆盖项清空，重新继承服务端。自动取料仍由 `schematicRefill` 独立控制，默认 `true`。该版本生成 `configVersion: 1` 文件；0.3.2 会按上节迁移为版本 2。请保留版本标记；备份不自动恢复，也不参与运行。需要恢复某些选择时，将所需选项填写到新文件并保留其版本标记。

备份失败或已存在内容不同的备份时，保留原文件并记录错误，不覆盖备份。损坏 JSON、未知配置版本和新版非法字段也会保留并报错。使用 0.3.2 的个人设置时两端都需更新；旧客户端不能把旧偏好重新上传。只用服务端收纳的玩家仍无需安装客户端模组。

## 安装

- 多人服务器：在 **Fabric 1.21.11 服务端** 的 `mods` 中安装本模组及对应版本的 Fabric API。玩家客户端无需安装本模组。
- 单人 / 局域网房主：在客户端实例的 `mods` 中安装同样的两个模组，由内置服务端执行收纳。
- 客户端单独安装不能让未安装本模组的远程服务器自动收纳。
- 使用 Fabric Loader **0.18.4 或更新版本**。项目开发和测试使用 0.19.5、Fabric API 0.141.6+1.21.11。

构建产物在 `build/libs`。安装普通 `.jar`，不要安装 `-sources.jar`。

### 图形设置（Mod Menu + YACL）

客户端可额外安装 [Mod Menu 17.0.1](https://modrinth.com/mod/modmenu/version/17.0.1) 和 [YACL 3.8.2（Fabric 1.21.11）](https://modrinth.com/mod/yacl/version/3.8.2+1.21.11-fabric)。它们是可选依赖，独立服务端无需安装。升级时移走旧版本本模组 JAR，避免重复加载。

入口：**模组 → Magic Shulker Boxes → 配置**。界面跟随游戏语言，支持简体中文和英文；每个选项都有说明。

- **个人设置**：布尔选项选择“继承服务端 / 开启 / 关闭”，腾栏方式也有“继承”选项。重置为“继承”会删除该个人覆盖项；取消或不保存退出不写入文件。
- **主菜单**：修改本地个人偏好，稍后加入允许个人设置的服务器时同步。
- **游戏内**：服务端需安装支持图形设置及恢复查询协议的本模组版本，且开启 `allowPlayerSettings` 才能从界面修改个人设置。保存等待服务器确认，成功后写回本地文件；服务器拒绝、频率限制和超时均有提示。关闭个人设置时锁定编辑。
- **世界设置 / 本地默认**：仅主菜单与单人 / 局域网房主可见，顶部直接切换，修改此实例的统一设置，包括独立的入盒、取料开关和“允许玩家个人设置”。保存后立即生效；加入远程服务器的玩家看不到此页。

两页独立保存；切换时若有未保存草稿，会提示丢弃或返回编辑。服务端策略或连接发生变化时，已打开的个人设置页需要重新打开，避免提交过期草稿。左侧名称为固定标签，右侧独立按钮点击切换可选值（右键反向切换），旁边的重置按钮恢复该项默认值。个人偏好可选择继承，世界设置直接选择实际值。选择“继承服务端”时，选项行直接显示收到的值，例如“继承服务端（开启）”；未连接或未收到该值时显示“未同步”，不会猜测默认值。服务端同步更新后显示随之刷新，旧草稿仍需重新打开。说明中也显示服务端默认值；服务端默认关闭入盒或取料时分别提示。只安装 Mod Menu 而未安装 YACL 时，配置入口会显示缺少依赖的提示。

“**拾取时自动入盒**”（`pickupStorageEnabled`）与“**Litematica 自动取料**”（`schematicRefill`）独立：可以只入盒、只取料、两者开启或两者关闭。`pickupStorageEnabled=false` 只关闭拾取入盒。若关闭个人设置并统一关闭两项功能，请同时设置 `schematicRefill=false`。

保存超过 10 秒未确认时，会暂停继续保存并查询服务端已保存的设置；迟到确认仍可处理。若本地文件写入失败，当前游戏和设置页仍使用服务端确认的值，并明确提示本地保存失败。未完成的保存会留下按服务器和玩家隔离的恢复标记；重连或重启客户端后先查询服务端，再恢复编辑，不会直接上传旧本地文件。同步完成后重新打开设置页。

## 原理图自动取料

客户端安装 **Litematica 0.26.16 / MaLiLib 0.27.20（Minecraft 1.21.11）**，客户端与服务端都安装 Magic Shulker Boxes **0.3.2**。新版不再接受旧取料协议，个人设置需使用本版的新同步协议。单人游戏只需在客户端实例安装；专用服务端不需要 Litematica 或 MaLiLib。

启用 Litematica 轻松放置，对准原理图并使用它的放置键。背包及副手已有材料时沿用原有行为；缺料时从潜影盒取出匹配材料，等服务端同步背包后继续放置。持续按住放置键即可继续；单次点击可能只完成取料，此时再点一次。支持旧版及重写版轻松放置。普通选取方块、创造模式、箱子界面及鼠标光标持物时不自动取料。

背包满时，默认把一栏物品直接收进来源盒腾栏，全程不丢物品。默认保护快捷栏，沿用 `useHotbarForSpace`、`allowPartialStacksForSpace`、`allowMixedItemsWhenMakingSpace` 设置。不会把潜影盒搬入另一个盒子。数量大于 1 的来源盒需要额外空栏拆出一个；没有安全空间时不修改物品。Carpet 通常只允许空盒堆叠，空盒中没有可取的材料。

取料优先选择未满盒，多个未满盒中先取装载程度较低的，尽量先用空一个盒子。满盒作为后备；无法安全取料的来源会被跳过。客户端查找和服务端实际取料都使用这一顺序，装载程度相同时按背包栏位顺序。

菜单新增“**原理图取料**”分组：

| 设置 | 默认 | 行为 |
| --- | --- | --- |
| `schematicRefill` | `true` | 独立控制自动取料；允许个人设置时，玩家可覆盖服务端默认值 |
| `refillFullStack` | `true` | 从盒内一个栏位取最多一组；关闭则取一个 |
| `refillMakeSpace` | `true` | 满背包时直接收纳腾栏，与拾取时的丢出模式独立 |
| `refillFailureMessages` | `true` | **仅在无法取料时**于快捷栏上方提示，每两秒最多一次；成功不提示 |

失败提示区分缺少匹配材料、空间不足、功能禁用和服务器不支持。关闭提示不影响取料行为。个人设置是否可修改仍由 `allowPlayerSettings` 控制。关闭拾取入盒后，取料仍可按 `refillMakeSpace` 将背包物品移入来源盒腾栏。

客户端查找材料时比较完整物品组件，包括自定义名称；请求还携带组件指纹，服务端发现来源已变化时会拒绝取料。无法可靠编码的临时组件同样拒绝。两端都需支持新的取料协议，旧协议不会绕过校验。只搜索普通背包及可选副手的潜影盒，不搜索末影箱或嵌套容器。客户端仅在缺料尝试时查询，每半秒最多请求一次；服务端核对真实盒内物品、游戏模式和界面状态。客户端不提供权威物品数据，也不预先修改背包。

## Carpet 堆叠兼容

可以与 Carpet 的 `stackableShulkerBoxes` 规则一起使用；本模组不会替你开启该规则，也不要求安装 Carpet。

数量大于 1 的潜影盒必须先拆出 **一个**，放到独立主背包或快捷栏栏位，才会修改其内容。默认先寻找现有可用盒子；仍有物品装不下且没有空栏时，会自动腾出一栏。不会借用装备栏、副手或鼠标光标，也不会搬走潜影盒来腾位置。

默认先走原版拾取，因此通常有空栏时物品会直接进背包，无须拆盒。若希望背包未满时也优先进入潜影盒，将 `onlyWhenInventoryFull` 设为 `false`；此时有空栏即可拆分堆叠盒。

### 自动腾栏

`makeSpaceMode` 有三种行为：

- `MOVE_TO_BOX`（默认）：把选中栏位的物品直接移入拆出的盒子，再由这个盒子占用该栏位，全程不落地。
- `DROP_AND_PICKUP`：在玩家脚下生成选中栏位的掉落物，拆出一个盒子，再立即通过游戏拾取流程收回到预留的盒子内。生成失败就不腾栏；若其他模组阻止回收，剩余物品保留在地面，带有禁止再次触发腾栏的标记。
- `DISABLED`：不主动腾栏，没有空栏就跳过堆叠盒，继续尝试其他盒子。

不要求物品满一组：3 个石头也可以腾栏，需将该栏的 3 个都移走才能空出栏位。默认只选择背包主区域，优先与拾取物同类，再考虑其他可入盒物品；可以另行允许使用快捷栏。移动前确认选中栏位的全部物品都能放下，并且仍能接收至少一个本次拾取物，否则不动背包。

允许混合收纳时，例如背包中 3 个石头腾栏，加上拾取的 5 个圆石，就得到装有两种物品的杂物盒。后续拾取砂砾等物品时，默认先复用这个杂物盒，不会每种物品都再拆一个空盒。关闭 `allowMixedItemsWhenMakingSpace` 后，腾栏只选择与本次拾取物同类的物品。已有同类专用盒不会因为腾栏混入无关物品。

支持原版所有颜色的潜影盒，保留盒子名称、颜色、其他组件和内部物品数据；不允许嵌套潜影盒。

## 配置

首次启动会在**执行收纳的一侧**生成 `config/magic_shulker_boxes.json`。多人服修改服务端文件；单人世界修改客户端实例文件。修改后使用管理员命令 `/msb admin reload`，或重启服务端/客户端。

[完整配置示例](https://github.com/chenjicheng/magic-shulker-boxes/blob/main/examples/magic_shulker_boxes.json)与默认值一致。

| 配置项 | 默认 | 含义 |
| --- | --- | --- |
| `allowPlayerSettings` | `false` | **仅服务端策略**：是否允许玩家个人设置；关闭时所有玩家统一使用本文件 |
| `pickupStorageEnabled` | `false` | 默认关闭；仅控制拾取时自动入盒，与自动取料独立；允许个人设置时，玩家可覆盖服务端默认值 |
| `onlyWhenInventoryFull` | `true` | 仅收纳原版背包装不下的余量；`false` 时先尝试潜影盒，再放背包 |
| `useMatchingBoxes` | `true` | 使用同类专用盒 |
| `useEmptyBoxes` | `true` | 使用空盒 |
| `useMixedBoxes` | `true` | 使用已有多种物品的杂物盒 |
| `allowOtherSingleTypeBoxes` | `false` | 前面所有可用方案都无法继续收纳时，允许混入其他单类盒 |
| `splitStackedBoxes` | `true` | 允许拆分堆叠盒，包括自动腾栏；关闭时整组跳过 |
| `makeSpaceMode` | `"MOVE_TO_BOX"` | 无空栏时直接收纳腾栏；可选 `"DROP_AND_PICKUP"` 或 `"DISABLED"` |
| `useHotbarForSpace` | `false` | 是否允许从快捷栏搬走物品腾栏；默认仅背包主区域 |
| `allowPartialStacksForSpace` | `true` | 是否允许未达到物品最大堆叠数的零散物品用于腾栏，两种腾栏方式都遵守 |
| `allowMixedItemsWhenMakingSpace` | `true` | 是否允许用不同种类的物品腾栏并形成杂物盒 |
| `preferExistingBoxesBeforeMakingSpace` | `true` | 先使用所有现有可用盒子，再尝试腾栏；`false` 时按原类别顺序遇到堆叠盒就尝试腾栏 |
| `includeOffhand` | `false` | 是否查找副手里的潜影盒；拆分目的地仍限主背包与快捷栏 |
| `matchItemComponents` | `false` | `false` 按物品 ID 判断种类；`true` 同时比较名称、附魔等组件 |

“一种物品”按种类而不是占用栏数计算：装有多组圆石的盒子仍是单类盒。无论如何设置种类判断，真正合并内部物品堆叠时都会严格比较组件，不会把不同附魔、名称或药水效果合并。物品各自的最大堆叠数仍然生效。

除 `makeSpaceMode` 使用上表中的字符串外，配置项只接受 JSON 布尔值 `true` / `false`，可以省略字段以使用默认值。无效 JSON、未知字段、未知模式或错误类型会记录错误并同时禁用自动入盒和自动取料，原文件保留，原版拾取仍可使用。

只处理地面物品与玩家接触时的拾取，不处理箱子转移、合成、命令发物品或丢弃操作；不扫描末影箱或其他嵌套容器。

## 玩家个人设置与语言

游戏内提示支持简体中文和英文，跟随玩家的 Minecraft 语言；未安装客户端模组的玩家也能看到服务端提供的对应语言回退。其他语言回退为英文。命令、JSON 字段和模式值使用固定英文名称，两种语言通用。模组显示名统一为 Magic Shulker Boxes，简介提供中英文。

服务端默认 `allowPlayerSettings=false`，忽略个人配置。管理员可以实时切换并保存：

```text
/msb admin player-settings true
/msb admin player-settings false
/msb admin reload
```

上述管理命令要求 Minecraft 的 `COMMANDS_ADMIN` 权限（通常为 OP 等级 3），服务端控制台也可执行。`allowPlayerSettings=false` 时，服务端的入盒和取料开关对所有玩家生效；设为 `true` 后，两项服务端值成为可覆盖的默认值。重载失败时保留此前有效配置。

开放个人设置后，普通玩家无需安装客户端模组即可使用：

```text
/msb
/msb show
/msb set pickupStorageEnabled false
/msb set schematicRefill true
/msb set makeSpaceMode MOVE_TO_BOX
/msb set allowPartialStacksForSpace true
/msb reset
```

`show` 显示当前**实际生效**的配置。`set` 立即生效，支持上表除 `allowPlayerSettings` 外的所有收纳选项；`reset` 清空个人覆盖项。命令带选项和值的补全。每人只能修改自己的配置，关闭个人设置后 `set/reset` 会被拒绝。

个人设置按 UUID 保存在当前存档的 `data/magic_shulker_boxes/players/<UUID>.json`，重启后保留，不同存档互不影响。只保存玩家修改过的选项，其他选项始终继承服务端当前默认值。管理员手动修复这些文件后，可用 `reload` 清除缓存。

### 可选的客户端同步

客户端安装本模组后，首次生成 `config/magic_shulker_boxes-client.json`，初始内容为 `{}`，表示全部继承服务端默认。可参考[个人设置示例](https://github.com/chenjicheng/magic-shulker-boxes/blob/main/examples/magic_shulker_boxes-client.json)。

加入支持本模组且允许个人设置的服务器时，客户端会自动提交此文件；服务器切换为允许或重载策略时也会重新同步。提交会替换此玩家在当前服务器保存的覆盖项。服务器关闭个人设置时不会上传，本地文件保留。修改本地文件后重新加入服务器即可同步。

通过 `/msb set/reset` 成功修改后，已安装模组的客户端会同步保存到本地个人文件，所以重新加入后仍保持一致。该本地文件由此客户端实例共用，会在其他允许个人设置的服务器上使用；纯服务端玩家只使用各存档中的服务器保存记录。同步只涉及收纳行为设置，不能更改服务端策略。
