# Magic Shulker Boxes 0.9.2

适用于 Minecraft 1.21.11 / Fabric / Java 21。

- 修复随身潜影盒菜单取物又收入来源盒、并可能重复保存物品的问题。保护依据真实容器所有权，不依赖第三方模组名称。
- 地面拾取与容器入包先完成原版来源扣减、权限检查和回调，再整理实际收到的物品。收纳数量受槽位增量及全背包相同组件物品的净增量限制，原版移动旧物品不再被当作新来源。
- 无法确认独立所有权的菜单保持原版转移；打开期间暂停 MSB 对随身盒子的收纳写入。取出的物品留在背包，不自动回流进正在编辑的盒子。
- 满背包导致原版容器拒收时，物品保留在原槽，不提前抽取或根据快照补发。地面仍存活、引用和数量符合原版结果的真实余量可在原版拾取结束后继续收纳。
- 已删除掉落物为原版回调恢复的堆叠数量不再作为可收纳来源。规划只移动真实已有物品，提交前核对实时库存。
- 保留 0.9.1 的物品内容分类与严格组件匹配设置。磁盘配置仍为版本 2，设置/GUI 协议仍为 v7，不新增字段或重置个人选择。

收纳规则与兼容边界见[使用说明](../guide.md)。服务器与客户端来源由[手动部署命令](../release-staging.md)同步更新。

## English

For Minecraft 1.21.11 / Fabric / Java 21.

- Fixes carried-shulker menu extraction returning to the source box and potentially persisting duplicate items. Protection verifies actual container ownership instead of matching third-party mod names.
- Ground pickup and container insertion finish vanilla source deductions, permissions and callbacks before organizing actual receipts. Storage is bounded by slot increases and the whole inventory's net increase for identical components, excluding rearranged older items.
- Menus without verified independent ownership retain vanilla transfers. MSB pauses carried-box storage writes while they are open, leaving extracted items in the inventory rather than returning them to the edited box.
- Container stock rejected by a full vanilla inventory remains in its source slot. Earlier snapshots never supply replacement items. A live ground remainder with the original stack reference and observed quantity may be stored after vanilla pickup completes.
- Stack counts restored on removed item entities for vanilla callbacks are no longer reusable sources. Plans move existing stock and verify live inventory before committing.
- Preserves 0.9.1 intrinsic-content classification and strict component preferences. Disk configuration remains version 2 and settings/GUI protocols remain v7, without new fields or preference resets.

See the [user guide](../en/guide.md) for storage and compatibility boundaries. [Manual deployment](../en/release-staging.md) updates server and client sources together.
